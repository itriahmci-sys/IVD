# 社區診所協作需求調查

這是原模擬器改製的問卷版本。五步填答、無病人資料、可留白、原始答案與試算分開。預估 6–10 分鐘，尚須以不同科別實際試填確認時間。

## 先試用

雙擊另附「社區診所參數調查_直接開啟版.html」。尚未設定收件端時會明示「預覽模式」，不會傳送資料。無需先填完所有數字即可查看儀表板；缺漏不當成零。

## 正式開放前需要的四項設定

1. GitHub Pages 網址，例如 https://account.github.io/clinic-survey/。
2. 主辦／資料管理單位名稱。
3. 聯絡及撤回管道（Email 或電話）。
4. 原始資料保存期間，例如「蒐集截止後12個月刪除原始回覆」。此項是主辦單位要履行的管理安排，程式不會自動刪除。

原模擬器的私密 Sites 權限不會沿用到 GitHub。這份問卷沒有帳號密碼；不要在前端或公開儲存庫放 Google 密碼、權杖、回覆資料或帳戶密鑰。

## 設定 Google Sheets（一次完成）

1. 在自己的 Google Drive 新建一個空白 Google Sheet，命名「社區診所協作需求調查」。保持非公開，只授權指定分析人員。
2. 開啟「擴充功能 → Apps Script」。將本包 `Code.gs` 全部貼入編輯器，取代預設的空白 myFunction。
3. 在程式中搜尋 `SETTINGS`，填入 `organizer`、`contact`、`retention`。把 `allowedOrigins` 改成 GitHub **來源網址**，例如 `https://account.github.io`；不含 `/clinic-survey/`。若改用自有網域，填自有網域的 HTTPS 來源。原始資料表 ID 不用放進 HTML。
4. 儲存。上方函式選單選 `setup` → 執行；由主辦帳號確認 Google 授權。程式會建立 `responses`、`欄位說明`、`單一中心規劃`、`調查說明`。若已有相同名稱且欄位不同會停止，不覆寫資料。
5. 「部署 → 新增部署 → 網頁應用程式」。執行身分選自己；若要讓院所不登入 Google 也能填答，存取者選「任何人」。這只開放寫入端，不代表公開 Google Sheet。Workspace 管理員可能限制這項選項；若沒有，請先確認組織政策，不要改成公開原始資料。
6. 複製正式 `/exec` 網址（不要用只供編輯者測試的 `/dev`）。
7. 修改 `config.js`：填入 `endpoint`，以及與 SETTINGS 相同的 `organizer`、`contact`、`retention`。兩端版本字串須一致。

Google 官方部署說明：https://developers.google.com/apps-script/guides/web

## 上傳 GitHub Pages

儲存庫網站根目錄需有：`index.html`、`styles.css`、`app.js`、`schema.js`、`config.js`、`.nojekyll` 及完整 `fonts/` 資料夾。只上傳這些前端檔即可；`Code.gs` 在 Apps Script 執行，不在 GitHub 執行。

在 GitHub「Settings → Pages」選擇發布分支與根目錄。此步會讓問卷頁對外可見，請在主辦資訊、同意文案及端對端試送確認後，由您決定正式發布。此交付尚未替您公開任何網站。

## 正式使用前一定要做一次試送

1. 用 GitHub 網址開啟，確認顯示正式調查及正確主辦資訊。
2. 填一筆明確的測試紀錄，在建議欄註明「部署驗證測試」。
3. 按送出，必須看到「已確認存入資料表」及編號；切到 Google Sheet 核對一列原始答案，確認空白與 0 分別保存。
4. 重試同一編號不應產生第二列。新開問卷的新編號仍會新增一筆。
5. 刪除測試列，再開放招募。

目前已完成本機瀏覽器及模擬 Google 服務的驗證，尚未在您的 Google 帳戶執行實際寫入。跨來源回覆採 HTML 表單 POST + Google 回執訊息，避免把「請求已送出」當成「已寫入」。若逾時，畫面會顯示未確認，保留同一編號重試；不要另起一份造成重複。

Apps Script 修改後須「管理部署 → 編輯 → 新版本」更新部署。若換成新 `/exec` 網址，記得更新 config.js。

## 每個欄位如何使用

- 地區、類別、科別、身分：分層檢視需求，不收具名診所資料。
- 每日人次 × 每月天數：月看診人次的粗估；不是不重複人數。
- 採購、IT、行政三項月支出：可共用支援的現況基準，不是診所總成本。
- 每週行政／IT 工時：全診所加總，不乘薪資或自動換算裁員。
- 願付費：月費上限，不是承諾或實際合約。
- 節省比例、工時減少比例：受訪者期待，不是已觀測改善。
- 原始資料月份與來源：判斷不同月份及估計值的可比性。
- FHIR、流程與保險協作態度：分開保存，不把不同同意範圍合併。
- 留白：未提供；0：明確沒有。禁止直接用零補所有缺漏。

## 個別 Dashboard

目前支援費＝採購＋IT＋行政。
期待節省＝目前支援費 × 期待節省比例。
情境支援費＝目前支援費 − 期待節省 ＋ 試算月費。
期待每週工時＝目前每週工時 ×（1 − 期待減少比例）。
資料不足就顯示「資料不足」，不帶入舊版示範預設。試算月費可以調整，但原始願付費不變。個別儀表板沒有其他診所資料讀取權限。

## 單一中心規模規劃

在「單一中心規劃」黄色格填實際固定成本 F、每家變動成本 v、增量協調係數 gamma、容量 K、增聘費 J、建置費 I 及攤提月數 M。

每家中心月費＝F/N + v + gamma(N−1) + J×max(0,ceil(N/K)−1)/N + I/(M×N)。

表中比較 5–200 家，並計算樣本中「願意／傾向／有條件」且願付費達門檻者。這不是需求預測：條件仍須滿足，樣本也不具代表性；同診所多人回答可能重複。本問卷沒有診所識別碼，僅防同一次傳送重複，不能驗證「一家一份」。如要推估獨立診所數，應另採主辦管理的邀請代碼設計並更新同意說明。

對外報告建議小樣本（例如 n<5）不揭露區域／科別細分。需另行分層抽樣、去除測試與異常資料、取得中心成本報價，才能評估規模經濟；不能把願望比例直接當成實際成本下降幅度。

## 安全及維護界線

後端檢查同意、欄位範圍、允許來源、版本與送出編號；在鎖定下防同編號重複，並將文字安全寫入儲存格，避免公式注入。GET 不提供回覆資料。

允許來源是部署配置檢查，不是使用者身分驗證，不能阻擋刻意偽造請求的程式。這是公開問卷接收端；大量招募或遇到濫用時，需增加真正的防機器人驗證、流量限制或邀請碼服務。不要把前端共用密碼視為安全措施。

暫存預設關閉；勾選才存本機瀏覽器。清除填答不會撤回 Google Sheet 的資料；主辦收到撤回要求後應按送出編號處理。保留期限屆滿須由主辦刪除及管理備份。

## 檔案

- `index.html`：問卷與自願同意聲明。
- `styles.css`：電腦與手機版面。
- `schema.js`：欄位、驗證規則與情境計算。
- `app.js`：步驟、Dashboard、暫存及送出回執。
- `config.js`：主辦資訊及收件網址（不含密碼）。
- `Code.gs`：Google Apps Script 接收器與資料表初始化。
- `欄位字典.csv`：研究資料欄位與單位。
- `test.cjs`：本機驗證腳本（需 Node、Playwright、Chromium）。
